# Tech Decisions — Whiteout (가제)

`minimal` 단계: ADR 대신 이 한 장에 기록한다. 게임 규칙은 `design/quick-specs/core-rules.md`.

1. **데이터:** 게임 수치는 모두 ScriptableObject. 코드에 직접 쓰지 않는다.
   나중에 스프레드시트(CSV) 테이블 → ScriptableObject 가져오기 도구 (MVP 밖).
   이유: 에디터에서 바로 수정하고 플레이 중에도 조율할 수 있다.
2. **스탯과 증강:** 스탯 = 기본값 + 수정자 목록(더하기 / 곱하기).
   수치형 증강 = 수정자 묶음(데이터만으로 만든다). ★ 규칙형 증강 = 증강별 코드.
   이유: 증강이 쌓여도 값이 왜 바뀌었는지 추적할 수 있고, 새 분야는 데이터만 추가하면 된다.
3. **로직과 테스트:** 규칙(허들, 환경 온도, 증강 적용)은 MonoBehaviour가 아닌 순수 C# 클래스로 둔다.
   싱글톤 대신 의존성 주입.
   테스트는 지금은 선택사항(`qa.level: minimal`)이다. 핵심 기능을 빨리 구현하고 눈으로 확인하는 것을 우선한다.
   테스트할 수 있는 구조는 유지해서 나중에 `Assets/Tests/EditMode/`에 추가한다.
4. **외형 분리:** 프리팹 루트 = 로직, 자식 = 모델. 리소스는 미정이며 처음에는 기본 도형으로 만든다.
5. **플랫폼:** Steam PC, 키보드+마우스, Input System. 게임패드는 나중에 입력 매핑만 추가.
6. **렌더링:** URP, 3D 로우폴리, 고정 60도 탑다운 카메라.
7. **코드 위치:** `Assets/Scripts/Systems/<시스템>/` (Survival, Environment, Camp, Gathering, Augments, Threats, RunFlow, Player).
   `Gathering`은 이전 이름 `Resources`를 바꾼 것이다 (지영 결정 2026-11-13). `Resources`는 Unity 특수 폴더 이름이라 그 안의 에셋이 모두 빌드에 들어가기 때문이다.
   **코드 반영은 S개발**: 실제 폴더는 아직 `Systems/Resources/`이고, 옮길 때까지 문서와 코드가 다르다.
8. **코드 구조:** 시스템당 어셈블리 2개(Logic / Unity), Core는 무참조, 조합 루트는 VContainer.
   상세: `docs/architecture/code-structure.md`
9. **VContainer 설치:** `Packages/manifest.json`에 git URL + 태그 고정
   `https://github.com/hadashiA/VContainer.git?path=VContainer/Assets/VContainer#1.19.0`
   설치 직후 컴파일과 간단한 주입이 되는지로 Unity 6.3 호환을 확인한다.
   **주의:** VContainer는 이름이 `LifetimeScope.cs`로 끝나는 새 파일의 `.meta`가 생길 때 그 파일을 빈 템플릿으로 덮어쓴다
   (패키지의 ScriptTemplateModifier). `Assets/Settings/VContainerSettings.asset`(Preloaded Assets에 등록)에서
   `DisableScriptModifier`를 켜 두었지만, **편집 모드에서는 막지 못한다** (2026-11-12 시험으로 확인).
   VContainer가 이 설정(`VContainerSettings.Instance`)을 플레이 모드에서만 읽기 때문이다.
   그래서 새 스코프 파일을 만든 뒤에는 에디터 임포트가 끝난 다음 반드시 내용을 다시 확인하고, 덮어써졌으면 다시 쓴다.
   (이미 `.meta`가 있는 파일은 다시 덮어써지지 않는다.)
10. **플레이어 이동:** CharacterController. 물리에 밀리지 않고 입력대로 정확히 움직인다.
11. **카메라:** Cinemachine(Unity 공식 패키지) `com.unity.cinemachine` 3.1.4 고정(Packages/manifest.json)으로 60도 탑다운 고정, 플레이어 추적.
    Unity 6.3은 기본으로 옛 2.10.4를 설치하는 알려진 문제가 있어 버전을 고정한다. 설치 직후 컴파일로 호환을 확인한다.
12. **씬:** Bootstrap 씬(공용 서비스·설정, 한 번만 생성) + Game 씬(추가로 불러옴). 재시작은 Game 씬만 다시 불러온다.
13. **온도 판정:** 장소 구역은 없다. View가 플레이어와 맵 중심 사이 거리(링), 근처 켜진 모닥불을 계산해
    Logic에 넘긴다. 트리거 볼륨은 쓰지 않는다. 은신처 휴식 범위 판정도 View가 한다.
14. **단위:** 거리 m, 속도 m/s, Unity 1유닛 = 1m. 그리드 판정은 쓰지 않는다.
15. **길찾기:** NavMesh(`com.unity.ai.navigation`). 적의 상태 전환은 Logic, 길찾기·이동은 View의 NavMeshAgent가 맡는다.
16. **시야 가림 판정:** View가 적의 눈 높이에서 플레이어까지 Physics.Linecast(레이캐스트)로 확인한다. 시야를 가리는 오브젝트는
    전용 레이어('시야 차단')로 구분해 데이터로 바꿀 수 있게 한다. 이 레이어에는 나무·바위·지형만 넣는다(설치물·아이템 제외, core-rules §6).
    감지와 놓침 모두에 쓴다. 결과(보임/가림)만 Logic에 넘긴다. 판정 주기 0.2초 (임시값).
17. **카메라 가림 처리:** 카메라와 플레이어 사이에서 시야를 가리는 나무·바위만 반투명으로 바꾸고, 벗어나면 되돌린다.
    대상은 가림 표시 컴포넌트(`CameraOccluder`)를 붙인 오브젝트뿐이다(바닥·가장자리 벽·플레이어 설치물 제외).
    View(Whiteout.Game 어셈블리, 카메라 연출)가 매 프레임 카메라→플레이어로 SphereCast(반경 0.5m, 임시값)해 판정하고,
    반투명 머티리얼(알파 0.3, 임시값)로 바꿔 끼운다. 나무 높이 8m는 그대로 둔다(16번 늑대 시야 가림에 쓰임).

18. **포커스 없는 플레이 확인 (에디터 전용):** Unity 창에 포커스가 없으면 에디터 플레이가 첫 프레임에서 멈춘다.
    Player Settings의 Run In Background는 이미 켜져 있지만 에디터 플레이 중 `Application.runInBackground`는 꺼져 있었다.
    그래서 에디터 전용 스크립트(`Whiteout.Editor` 어셈블리, 빌드 제외)가 플레이 시작 때 `Application.runInBackground = true`로 켠다.
    빌드된 게임의 동작(포커스를 잃었을 때)은 바꾸지 않는다. Interaction Mode 변경은 필요 없었다.
    **입력:** Input System은 포커스가 없을 때 키보드를 끄고(`ResetAndDisableNonBackgroundDevices`), 에디터에서는 Game 뷰 포커스가
    있을 때만 키보드를 받는다(`PointersAndKeyboardsRespectGameViewFocus`). 이 값은 프로젝트에 영구로 바꾸지 않는다(개발 중 다른 창 입력이
    게임으로 들어가기 때문). 자동 확인(MCP) 때만 실행 중에 `IgnoreFocus` / `AllDeviceInputAlwaysGoesToGameView`로 바꾸고, 꺼진 장치는
    `InputSystem.EnableDevice`로 다시 켜고, 끝나면 원래 값으로 되돌린다. (이 프로젝트에는 Input System 설정 에셋이 없어 이 변경은 파일에 남지 않는다.)

19. **시작 위치 장애물 회피:** Logic(`PlayerStartPicker`)이 안쪽 링 안에서 후보를 뽑고, View(`PlayerController`)가 그 자리에
    플레이어 크기 + 여유 0.5m(임시값)만큼 충돌체가 있는지 `Physics.CheckCapsule`로 확인한다(바닥·트리거 제외).
    겹치면 다시 뽑고, 최대 30번(임시값) 실패하면 맵 중심(장애물을 두지 않는 자리, core-rules §5)에서 시작한다.
    여유와 시도 횟수는 `PlayerConfig` 데이터.
20. **개발용 디버그 표시:** 링 선 같은 디버그 표시는 `Debug.isDebugBuild`가 참일 때만 켠다(에디터, Development Build).
    실제(릴리스) 빌드에서는 그리지 않는다. Scene 뷰 Gizmos는 원래 에디터 전용이다.

21. **Play는 항상 Bootstrap에서 시작 (에디터 전용):** 에디터에서 어떤 씬을 연 채 Play해도 Bootstrap 씬부터 시작한다
    (`EditorSceneManager.playModeStartScene`). Game 씬만 열고 Play하면 Bootstrap 스코프가 없어 주입이 실패하기 때문이다.
    시작 씬은 Build Settings의 0번 씬(Bootstrap, 12번)을 쓴다. Unity 메뉴 `Whiteout > Play From Bootstrap`으로 끄고 켤 수 있고
    (기본 켜짐), 이 값은 이 PC의 에디터 설정(EditorPrefs)에만 저장된다. 샌드박스 씬을 단독으로 시험할 때만 잠깐 끈다.
    `Whiteout.Editor` 어셈블리에 있어 빌드에는 영향이 없다. Play를 멈추면 에디터는 원래 열려 있던 씬으로 돌아간다.

22. **밤·눈보라 시야 표현 (임시값, 플레이 후 조정):** core-rules §3 시야 규칙을 View(`EnvironmentView`)가 표현한다.
    값은 모두 `EnvironmentConfig` 에셋(Look 항목)에 있고 코드에 없다.
    - 밤: 해(Directional Light) 밝기 ×0.05, 환경광(`RenderSettings.ambientIntensity`, 환경광 소스 Skybox 필요) ×0.1,
      플레이어를 따라가는 점광원(범위 12m, 따뜻한 색, 밝기 3)을 켠다. 모닥불 빛은 불 자체의 조명이 더한다.
    - 눈보라: 선형 안개(`RenderSettings.fog`), 색 (0.82, 0.87, 0.92). 안개 거리는 카메라 기준이라 카메라→플레이어 거리 + 15m에서
      흐려지기 시작해 15m(falloff) 뒤 완전히 가린다.
      현재 탑다운 카메라 화면은 플레이어 주변 약 12m만 보여서 이 안개는 화면에 거의 드러나지 않는다.
      안개 거리·카메라는 그대로 두고 플레이 후 다시 판단한다 (지영 결정, 2026-11-13).
    - 낮↔밤, 안개 켜고 끄기는 1초에 걸쳐 바뀐다. 겹치면 12m 빛이 15m 안개보다 안쪽이라 자연히 더 좁은 쪽이 된다.
    - 빌드에서 안개 셰이더 변형이 빠질 수 있으므로 릴리스 빌드 전 Graphics > Fog Modes에 Linear를 포함해야 한다 (미적용).
    - HUD(날씨·기온 글자): 흰 글씨 + 검은 외곽선, 크기 40, 왼쪽 위 (임시값, uGUI 레거시 Text).
      **배치 변경 (지영 결정 2026-11-13, `design/ux/ui-plan.md` §7.1 D2):** 기온은 왼쪽 위(날짜·낮/밤 진행과 함께),
      오늘·내일·모레 예보는 위쪽 가운데로 옮긴다. 현재 코드는 이전 배치(모두 왼쪽 위)이고 story-004 HUD 작업에서 맞춘다.
      → **ui-plan §7.1 우선 (지영 확정 2026-11-13, T1~T7):** 위 배치 메모는 타임라인 배치로 대체됐다. 기온은 위쪽 가운데에 크게,
      날짜·낮/밤·예보는 그 오른쪽 예보 타임라인 막대로 간다. 구현은 story-004가 아니라 `story-010-hud-forecast-timeline.md`.

23. **허들 임시값 (임시, 지영 확인 필요, story-003):** core-rules §2에 없는 값·정책을 임시로 정했다. 수치는 Survival 설정 에셋에 있다.
    - 시작 값: 체온·허기·체력 모두 100 (임시).
    - `PlayerDied` 원인: 체온 0과 허기 0이 함께 체력을 깎다 0이 되면, 그 틱에 체력을 더 많이 깎은 쪽을 원인으로 한다.
      같으면 동사(체온) (임시).
    - 사망 후: 허들 Tick과 플레이어 이동이 멈춘다. 결과 화면은 story-006.
    - 한 틱 안의 순서: 체온 변화는 이번 틱에 허기가 줄기 전의 허기 상태(30 미만 여부)로 계산한다. 체온·허기를 먼저 바꾸고,
      바뀐 값으로 체력 피해 또는 회복을 정한다. 피해가 있는 틱에는 회복하지 않는다 (임시).
    - 경계: 0 판정은 0 이하, '30 미만'은 30 미포함, 회복 조건 '60 이상'은 60 포함. 체온이 오를 때는 ×1.5를 적용하지 않는다.
    - 게이지 현재 값은 `Stat`의 기본값에 0~100으로 저장한다. 판정과 HUD는 수정자를 포함한 최종값을 읽는다 (임시).
    - 불이익 값은 줄어드는 비율로 저장한다: 이동속도 0.25, 채집속도 0.3 (`SurvivalConfig`).
    - 이동속도 불이익과 사망 시 이동 정지는 Game의 `SurvivalPlayerBridge`가 연결한다 (code-structure §4).
      사망하면 `PlayerController`를 끈다(이동·모델 회전 정지). 수정자 출처 이름은 `survival.cold`.
    - 엔진 점검 지적 2건은 이번 스토리에서 수정함 (지영 지시, 2026-11-13): `SurvivalPlayerBridge`는 플레이어가 파괴된 뒤에는
      아무것도 하지 않는다. `SurvivalConfig`는 에디터에서 값을 바꿀 때 최대값을 1 이상, 시작 값을 0~최대값으로 맞춘다
      (최소 1은 0으로 나누기를 막는 검증용 하한이다).
      `Whiteout.Survival.Unity`는 쓰지 않는 참조(`UnityEngine.UI`, `Whiteout.Core.Unity`)를 뺐다. 필요해지면 다시 넣는다.
    - 게이지 HUD (임시값, uGUI): 날씨 글자 아래 왼쪽 위, 한 줄에 글자(체온 / 허기 / 체력, 흰 글씨 + 날씨 글자와 같은 검은 외곽선, 크기 32) +
      막대(300×28, 배경 검정 60% 투명도). 막대 색: 체온 주황 (0.95, 0.45, 0.20), 허기 노랑 (0.90, 0.75, 0.20),
      체력 빨강 (0.85, 0.20, 0.25). 줄 간격 44. 막대는 스프라이트 없이 오른쪽 앵커를 비율로 옮겨 채운다.
      **배치 변경 (지영 결정 2026-11-13, `design/ux/ui-plan.md` §7.1 D2):** 게이지는 왼쪽 위 그대로, 날짜·기온 아래에 둔다
      (예보가 위쪽 가운데로 빠지므로 위치가 올라간다). 크기·색은 위 임시값 유지. story-004 HUD 작업에서 맞춘다.
      → **ui-plan §7.1 우선 (지영 확정 2026-11-13, T1):** 날짜·기온이 위쪽 가운데로 빠지므로 왼쪽 위에는 게이지만 남는다.
      크기·색 임시값은 그대로. 배치 이동은 `story-010-hud-forecast-timeline.md`.

24. **UI 기술과 문구 (지영 결정 2026-11-13, `design/ux/ui-plan.md` §12 D9~D12):**
    - UI는 uGUI + TextMeshPro. 레거시 `Text`(22·23번 HUD)는 TextMeshPro로 바꾼다 (D10).
    - UI 문구는 한국어만 쓰고, 코드에 직접 쓰지 않고 데이터로 분리한다 (D9). 데이터 형식은 처음 적용하는 스토리에서 정하고 여기에 기록한다.
      현재 `WeatherHud.cs`의 기본 문구(story-002 Deviations)도 이 규칙에 맞춘다.
    - 게임패드는 MVP 이후, 입력 매핑만 추가한다 (5번 유지, D11). UI는 마우스 전용 동작을 만들지 않는다.
    - 기온 원인 분해 표시(기본·날씨·링·불·증강)는 MVP 이후 (D12).
    - 폰트: Noto Sans KR (지영 확정 2026-11-13). TextMeshPro 폰트 에셋으로 만들어 모든 UI 글자에 쓴다.
    - HUD 상단 배치는 `design/ux/ui-plan.md` §7.1(기온 위쪽 가운데 + 예보 타임라인 막대, 지영 확정 2026-11-13 §7.5 T1~T7)을 따른다.
      22·23번의 배치 메모보다 이 문서가 우선한다.

28. **아이템·가방·설치 임시값 (임시, 지영 확인 필요, story-004):** items·core-rules·ui-plan에 없는 값·정책을 임시로 정했다.

    - **줍기:** 맵의 줍기 1개 = 아이템 1개(나무 50 = 줍기 50개). 채집 거리 2m. 후보 지점은 씬에 170개(안쪽 링 70, 가운데 60, 바깥 40)이고 그중 106개에 놓인다.
    - **첫날 보장:** 시작 위치에서 가까운 후보 20곳 안에 나무 6, 열매 5를 놓는다(전체 개수에 포함).
    - **가방:** 쓴 칸은 앞쪽으로 채워진다(칸이 비면 뒤 칸이 당겨짐). 칸 수는 스탯 값의 반올림. 칸 수가 줄어도 가진 것은 잃지 않고 더 넣지 못할 뿐이다.
    - **버리기:** 그 칸 전체를 한 덩어리로 발밑에 놓는다. 좌클릭도 칸을 고른다. 칸 메뉴는 우클릭·Esc·가방 변화·항목 선택으로 닫힌다.
    - **사용:** 즉시 적용, 게이지가 가득 차 있어도 쓸 수 있다(아이템은 소모). 사망 후에는 효과가 없다.
    - **요리:** 가방에서 앞쪽의 구울 수 있는 아이템부터 굽는다. 켜진 모닥불의 온기 반경(4m) 안이면 된다.
    - **E 우선순위:** 여러 행동이 가능하면 요리 40 > 나무 넣기 30 > 휴식 20 > 줍기 10. E를 새로 눌러야 시작하고, E 행동 중에는(휴식 포함) 이동할 수 없다.
    - **모닥불:** 나무 넣기·재점화는 E 0.5초, 거리 2m. **첫 점화와 재점화 모두 나무 2개다 (지영 확정 2026-11-13).**
      넣은 나무 2개는 연료 120초가 된다. 첫 점화는 부싯깃을 더 내지 않는다(설치 때 낸 부싯깃이 첫 점화).
      재점화의 부싯깃 1개와 부싯돌 조건은 core-rules §4 그대로 두었고, 통일 범위에 들어가는지는 지영 확인 필요(`design/ux/ui-plan.md` §8.2 M6).
      (이전 임시값: 첫 점화는 나무 1개. **코드 반영은 S개발**, 반영 전까지 코드는 나무 1개다.)
      꺼진 불에는 나무 1개만 넣을 수 없고 점화(나무 2개)해야 한다. 남은 시간 + 60초가 300초를 넘으면 더 넣을 수 없다.
      연료 표시는 6m 안의 가장 가까운 모닥불 1개만, 칸 수 = 올림(남은 초 / 60).

    - **장애물 레이어:** 나무·바위를 `Obstacle` 레이어(6번)로 옮겼다. 설치 가림 판정에만 쓴다. 16번의 '시야 차단' 레이어는 story-007에서 정한다.
    - **키 입력:** E, B, 좌클릭, 우클릭/Esc, 1~9, 휠은 코드에서 만든 InputAction이다(`InputSystem_Actions.inputactions`에 없음). 게임패드 매핑을 넣을 때 에셋으로 옮긴다.
